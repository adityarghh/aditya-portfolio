Baby Steps
to the Mic.

A small way back to speaking — built for the practice I needed, and for anyone else who might need it too.

ROLE
Product idea, design & development
BUILT WITH

FORMAT
Browser-based speaking practice
01THE REASON

I wanted a way to start again.

After a stretch of feeling stagnant, I noticed that public speaking — and even expressing myself confidently — had become harder. I couldn't point to one neat reason. I just knew I wanted to do something about it.

So I started building something I could use myself: a place to practise speaking without needing an audience, a perfect topic, or a whole plan. The idea was to make starting small feel normal.

And I didn't want it to be useful only to me. If I was struggling to get the words moving again, someone else might appreciate a low-pressure way to practise too.

02THE EXPERIENCE

Make the first minute easier.

The hardest part of practising on your own can be deciding what to say. Baby Steps starts with a prompt library and an animated topic spinner, so the user can get a subject and begin instead of spending the session choosing one.

A speaking timer gives the attempt a clear shape. It can be adjusted, paused, and resumed, with a circular progress ring and a visual cue as time runs low. Live transcription makes the spoken words visible while the session is happening, alongside a running word count.

Those choices are intentionally simple: pick a prompt, start talking, and stay with it for a little while. The product is meant to help someone begin practising, not make the act of practising feel like another complicated task.

03THE FEEDBACK LOOP

Not just a score. A next step.

After a session, the app sends the speaking topic and transcript to Claude for evaluation. The response is structured around a score from 1 to 10, an overall verdict, strengths, improvement suggestions, and extra angles the speaker could explore.

The point isn't to make a number the final word on someone's speaking ability. It's to turn one attempt into something the user can look at, learn from, and use to guide the next one. The results interface presents the score visually and breaks the feedback into scannable sections.

That structure also gives the AI a clear job. Rather than returning an unbounded paragraph, it returns fields the interface can present consistently.

04UNDER THE HOOD

Keep the browser experience simple. Keep the secret server-side.

The frontend is built with vanilla HTML, CSS, and JavaScript. Speech recognition uses the browser's Web Speech API to transcribe the session in real time; it works best in Chromium-based browsers, so that compatibility is worth knowing up front.

When the user asks for feedback, the app sends the topic and transcript to a Vercel serverless function. That function calls the Anthropic Claude API using an API key stored in Vercel's environment variables, rather than exposing the key in client-side code. The response is parsed into structured fields, with safeguards for model output and error handling for failed requests.

That separation gave the project a small footprint without putting the AI integration directly in the browser: one focused frontend, one serverless evaluation endpoint, and a clear handoff between them.

05WHAT CHANGED

A project that gave me a reason to practise.

Building it gave me a way to act on a problem I had been sitting with. Using it has helped me feel more comfortable speaking again — not as some dramatic before-and-after, but as a small, practical step in the right direction.

That is also why the name matters to me. The goal was never to become a perfect speaker in one session. It was to make it easier to show up, try, get a little feedback, and try again.

There is more I could add, including session history and ways to track progress over time. For now, the core loop is the part I wanted to make real: a prompt, a speaking attempt, and feedback that gives you somewhere to go next.
